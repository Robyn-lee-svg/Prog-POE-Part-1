POE PART 1: 
SYSTEM DESIGN AND PLANNING:
The main purpose of part 1 is on planning and designing the RaceDay event management system before 
the API was to be developed.

ENTITY RELATIONSHIP DIAGRAM(ERD):
An ERD was created to showcase the structure of the RaceDay database, including the main entities,
attributes, primary keys, foreign keys and relationships between entities.

DATABASE DESIGN:
The database design was designed to support the management of users,events, even catagories, participant
enrolment and race results. Relationships between entities were planned before implementation to ensure
that the database structure supports the system.

API ENDPOINT PLAN:
The API Endpoint Plan was created to help identify the REST API Endpoints that will be needed for the
RaceDay system. The planned endpoints cover: Authentication and registration, user profiles, events, categories,
event enrolment and results. Each endpoint specifies the HTTP method, route, description, role required, request 
body and expected response.
